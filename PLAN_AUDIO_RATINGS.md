# План: оценки отправленных аудио

## Цель

После успешной отправки аудио бот показывает inline-панель с оценками от 1 до 5.
Выбранная оценка сохраняется в SQLite. Команда `/rated` выводит только аудио,
оценённые вызвавшим её пользователем, по убыванию оценки.

## Принятое правило

Оценки персональные: одна и та же запись может иметь разные оценки у разных
пользователей. Это исключает влияние чужих предпочтений на личный рейтинг.
Повторное нажатие меняет предыдущую оценку, а не создаёт вторую запись.

## Изменения данных

1. В `init_db()` добавить таблицу `audio_ratings`:
   - `user_id INTEGER NOT NULL`;
   - `video_id TEXT NOT NULL`;
   - `rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5)`;
   - `title TEXT NOT NULL`;
   - `uploader TEXT`;
   - `rated_at TEXT NOT NULL`;
   - первичный ключ `(user_id, video_id)`.
2. Добавить индекс по `(user_id, rating DESC, rated_at DESC)` для `/rated`.
3. Реализовать `save_rating()` через SQLite upsert: новая оценка вставляется,
   существующая обновляется вместе с метаданными и временем.
4. Реализовать `get_rated_audio(user_id, limit)` с сортировкой `rating DESC`,
   затем `rated_at DESC`.

## Интерфейс Telegram

1. Добавить `rating_keyboard(video_id)` с пятью inline-кнопками: `1`, `2`, `3`,
   `4`, `5`. Значение callback: `rate:<video_id>:<rating>`.
2. При отправке результата прикреплять панель к последней аудиочасти. Это даёт
   ровно одну панель для многосоставного файла.
3. При cache hit использовать ту же панель, чтобы повторно выданное аудио тоже
   можно было оценить.
4. Добавить `CallbackQueryHandler`:
   - проверить формат callback и диапазон оценки;
   - сохранить оценку для `query.from_user.id`;
   - ответить на callback подтверждением;
   - обновить панель, пометив выбранную кнопку, например `4/5`.
5. Добавить `/rated`:
   - если оценок нет, показать понятное пустое состояние;
   - иначе вывести нумерованный список: оценка, название, автор и ссылка на
     YouTube;
   - ограничить выдачу, например 30 записями, чтобы не превысить лимит Telegram.

## Обработка краевых случаев

1. Для многосоставного аудио рейтинг относится к `video_id`, а не к части.
2. Отправка части, оценка и список не должны зависеть от доступности файлов в
   `/tmp`: все нужные метаданные хранятся в SQLite.
3. Callback от старого сообщения должен работать после перезапуска: он содержит
   только `video_id` и оценку, а название/автор при необходимости берутся из
   `cached_files` или из данных callback-сообщения.
4. Ошибки SQLite не должны прерывать отправку аудио: их нужно логировать и
   показать пользователю краткое уведомление.

## Проверки

1. Тесты SQLite в временной БД: вставка, смена оценки, изоляция двух
   пользователей, сортировка и фильтрация только оценённых записей.
2. Тест построения клавиатуры и разбора callback, включая некорректные значения.
3. Ручной smoke-test: обычная отправка, cache hit и многосоставной результат;
   на каждом случае выбрать оценку и выполнить `/rated`.
4. Регрессия: запустить существующие проверки загрузки и убедиться, что кэш,
   `/cancel` и `/stats` продолжают работать.
